**dgxtop** is a terminal GPU monitor built for NVIDIA DGX Spark: every GPU, each job's share of its memory and the whole machine on one screen, plus a record of every GPU job from start to end. It runs on any Linux machine with NVIDIA GPUs.

## New in v2.7.0

- **Two history tabs.** The history's charts were one page, and switching the GPU changed two of its six charts. Now `3` is the **Overview History**, the whole machine whatever GPU you look at: the CPU, the memory with its pressure, every temperature the machine reports, its power, the disk and the network. `4` is the **GPU History**, one GPU: every chart on the page is that GPU's, so `↑` / `↓` change all of them.
- **Every temperature in one panel.** The Overview History charts each CPU package, the SoC, each GPU and the drive, all against the same 100 °C.
- **More of each GPU.** Under a GPU's utilization, the share of time its memory was read or written; under its temperature, its fan's speed. A fan that never turned, or a memory activity that stayed at zero, has no chart, so no chart stands empty on a DGX Spark.
- **A slowed GPU's banner says what to do.** It names the reason in plain words (the power limit, the voltage limit, the board limit, heat or a hardware signal), the clock against the boost maximum, whether that is expected under load and how far the power limit can be raised (`GPU 0 slowed down: at its power limit of 360 W · clock 2715 MHz (boost max 3090) · expected under heavy load; raising the power limit (up to 390 W) lifts it · Esc hides`). `Esc` hides it once known, until a new reason appears.

## Changed

- The number keys follow the tabs: `3` Overview History, `4` GPU History, `5` Process History, `6` or `F2` Settings.
- A fold key acts on the tab shown: `c`, `m`, `t`, `p`, `i`, `n` on the Overview History, `u`, `v`, `t`, `p` on the GPU History, and `o` unfolds the tab's panels. Only the memory's pressure strips start folded now. A saved configuration that folded the old temperature or power panel still loads; that fold is left out at the next save.
- A machine that reads only its GPUs' power, such as a DGX Spark, titles the Overview History's power panel `Power · GPU`, so a GPU's draw is not read as the machine's.
- The history keeps three more series in every bar size: the fan's speed, the drive's temperature and the GPU's memory activity. The fans and the drive are recorded from this version on.
- A configuration saved by this version with a temperature or power panel folded is refused by an older dgxtop.
- Built with Rust 1.100.0 and SQLite 3.54.1. dgxtop's own code has no `unsafe` left.

## Fixed

- A GPU held at its voltage limit or its board limit was reported as power capped, with a percentage that read as a loss: the driver's two newer reasons were dropped.

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/DennySORA/dgxtop/main/install.sh | bash
```

Linux on x86_64 or aarch64 with glibc 2.34 or newer (Ubuntu 22.04, Debian 12, RHEL 9 and later), DGX Spark included; WSL 2 runs the Linux build. The installer checks the archive against `SHA256SUMS` and keeps the previous version for `./install.sh --rollback`. `dgxtop-v2.7.0.cdx.json` lists the dependencies (CycloneDX SBOM).
