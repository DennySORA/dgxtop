**dgxtop** is a terminal GPU monitor built for NVIDIA DGX Spark: every GPU, each job's share of its memory and the whole machine on one screen, plus a record of every GPU job from start to end. It runs on any Linux machine with NVIDIA GPUs.

## New in v2.4.0

- **Tell your GPUs apart.** Each GPU has a color of its own, the same in every view and theme: its lines on the Overview, its number in the process table, the GPU view, the Overview History's GPU picker and the Process History's runs and charts. Where a GPU was named by its number alone, its model now goes beside it (`GPU 0 · RTX 5080`). The numbers are the driver's, as `nvidia-smi` shows them; CUDA counts the fastest GPU first unless `CUDA_DEVICE_ORDER=PCI_BUS_ID` is set, so the model tells which card a job's `cuda:0` is.
- **Each GPU of a run.** An opened run in the Process History shows each GPU it used apart: its utilization and its memory there (`util 0`, `mem 0`), or the GPU's own utilization (`dev 0`) where the driver gives none per process, as on the GB10. A run on more than four GPUs adds the sums, and runs recorded by earlier versions show the sums.
- **Zoom the GPU processes.** `z` shows the process table alone on the Overview, with every row the terminal holds; selecting, sorting, filtering, `K` and `F9` work as always. `z`, `Esc` or another view brings the other panels back.
- **Pages under a fixed top.** The GPU view and an opened run keep their top in place and turn pages under a line that says the page, what the next one holds and the keys. An opened run's details read as aligned keys and values, a long path cut in its middle so its file name stays.

## Changed

- On an opened run, `↑` / `↓`, `PgUp` / `PgDn` and `g` / `G` turn its pages, and no key switches to another run: `Enter` goes back to the list.
- The Process History records each GPU of a run apart. v2.3.0 and earlier cannot read the runs this version records and start with an empty Process History; nothing is deleted.

## Fixed

- A GPU without a power limit, such as the GB10, no longer shows its power bar red and full while idle: the bar's scale is the highest draw the history on disk recorded in the last 30 days, and until that history reaches back past today the bar shows the draw alone.
- A GPU with no process on it shows `0 B` held by processes instead of unavailable, as on an idle GB10's RAM line.
- An opened run's panels pair up, so the network panel no longer stands alone in a half-empty row: the run's GPU utilization and memory share one panel.
- With the GPU filter on, the process table's title reads `GPU 0` instead of `GPU GPU 0`.

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/DennySORA/dgxtop/main/install.sh | bash
```

Linux on x86_64 or aarch64 with glibc 2.34 or newer (Ubuntu 22.04, Debian 12, RHEL 9 and later), DGX Spark included; WSL 2 runs the Linux build. The installer checks the archive against `SHA256SUMS` and keeps the previous version for `./install.sh --rollback`. `dgxtop-v2.4.0.cdx.json` lists the dependencies (CycloneDX SBOM).
